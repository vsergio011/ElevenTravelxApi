# ElevenTravel API

## Stack

- Go
- REST API
- Supabase authentication
- PostgreSQL
- Cloudflare R2

## Architecture

Organize backend code by domain.

Prefer:

internal/
  <domain>/

When appropriate, separate:

- HTTP handlers
- services
- repositories
- DTOs
- validation
- authorization

Business rules and authorization belong in the backend.

Do not duplicate complex business rules between frontend and backend.

## API

The API uses `/v1`.

Do not invent endpoints.

Before creating or modifying an endpoint:

1. Find equivalent endpoints.
2. Follow existing conventions.
3. Reuse request/response structures.
4. Reuse error conventions.
5. Reuse pagination.
6. Reuse authorization.

## Security

The backend must verify:

- authentication;
- permissions;
- group/planning membership;
- ownership;
- business rules.

Never trust client-provided authorization or ownership data.

## Supabase

Supabase authentication is validated by the Go API.

The frontend must not bypass the API for business logic.

Do not expose sensitive credentials.

## R2

R2 credentials must never reach the client.

Uploads must use signed URLs generated by the Go API.

## Database

Follow existing PostgreSQL and migration conventions.

Do not introduce a new persistence pattern without a concrete reason.

When a backend task depends on the current PostgreSQL schema or persisted data,
use the `supabase-database` skill.

Do not infer the current database state solely from Go models or migration files.
